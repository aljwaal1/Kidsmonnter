# تقدم KidsMonnter — مهلة محاولات تشغيل شاشة القفل

## ما تمت مراجعته

- آخر حالة بناء بعد تحسين مهلة استعادة خدمة الخلفية.
- `native/MainActivityV2.kt`، خصوصًا `MonitorService` و`enforceLockIfNeeded` و`showLock`.
- مسارات استعادة الخدمة وWatchdog ونبضة الخدمة.
- إشعار الخدمة وفتح لوحة التطبيق منه.
- اختبارات العقود ومسار GitHub Actions.

## المشكلة

بعد انتهاء الوقت، ينفذ المؤقت داخل `MonitorService` كل ثانية. كانت كل دورة تستدعي `showLock()` وتطلب تشغيل `LockActivity` ما دام الوقت منتهيًا والشاشة تعمل. إذا قيّد Android فتح النشاط من الخلفية أو تأخر في تنفيذه، تتراكم محاولات تشغيل جديدة كل ثانية دون مهلة.

## التغيير المنفذ

- إضافة ثابت `LOCK_LAUNCH_COOLDOWN_MS` بقيمة 5 ثوانٍ.
- حفظ وقت آخر محاولة تشغيل باستخدام `SystemClock.elapsedRealtime()`.
- تجاهل المحاولات المتكررة خلال المهلة.
- إبقاء إعادة المحاولة ممكنة بعد انتهاء المهلة إذا لم تظهر شاشة القفل.
- عدم تغيير احتساب الوقت أو PIN أو شروط انتهاء المدة أو صلاحية Overlay.

## الاختبارات

أضيف `test/lock_launch_cooldown_contract_test.dart` للتحقق من بقاء:

- المهلة المحددة.
- الساعة الرتيبة.
- حالة آخر محاولة تشغيل.
- شرط منع التكرار.
- استمرار استدعاء `LockActivity` بعد السماح بالمحاولة.

كما تم تحديث مسار البناء لدمج التغيير والتحقق منه قبل التحليل والاختبارات وبناء APK.

## ما بقي

- انتظار نجاح GitHub Actions وظهور APK جديد.
- اختبار انتهاء الوقت على هاتف حقيقي مع التطبيق في الخلفية.
- التأكد من ظهور شاشة القفل مرة واحدة دون وميض أو محاولات متكررة.
- الاستمرار في اختبار قيود البطارية الخاصة بالشركة المصنعة؛ لا يمكن ضمان تجاوز القتل القسري للنظام من خلال اختبارات المستودع وحدها.
