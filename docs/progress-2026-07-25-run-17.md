# Kidsmonnter — Run 17

## ما تمت مراجعته

- آخر بناء ناجح بعد دمج الاستعادة التلقائية لخدمة الحماية.
- `native/AndroidManifest.xml` والتأكد من إعلان `POST_NOTIFICATIONS`.
- مسار `startProtection` داخل `native/MainActivityV2.kt`.
- مسار GitHub Actions الذي يدمج ملفات Native ويشغّل التنسيق والتحليل والاختبارات وبناء APK.

## المشكلة المكتشفة

كان التطبيق يعلن إذن الإشعارات في Manifest، لكنه لا يطلبه وقت تفعيل الحماية على Android 13 وما بعده. هذا قد يترك خدمة الحماية بلا إشعار ظاهر، ويصعّب على المستخدم اكتشاف أن الخدمة تعمل أو أن النظام قيّدها.

## التغيير المنفذ

- إضافة `requestNotificationPermissionIfNeeded()` في طبقة Android Native.
- طلب `POST_NOTIFICATIONS` فقط على Android 13 وما بعده، وفقط عندما لا يكون الإذن ممنوحًا.
- استدعاء الطلب عند تشغيل الحماية، قبل تشغيل `MonitorService`.
- عدم تغيير المدة اليومية أو الوقت المستخدم أو PIN أو حالة فتح الهاتف لبقية اليوم.
- إضافة اختبار عقد يضمن بقاء الإعلان والطلب وربطهما بمسار `startProtection`.
- تحديث GitHub Actions لدمج التغيير والتحقق منه قبل التحليل والاختبارات وبناء APK.

## ما لم يتغير

- احتساب وقت الاستخدام.
- Watchdog واستعادة الخدمة.
- شاشة القفل وOverlay.
- منع الحذف وDevice Owner.
- تخزين PIN والبريد والمحاولات الفاشلة.

## ما بقي

- انتظار اكتمال GitHub Actions وظهور APK جديد.
- تجربة رفض الإذن وقبوله على جهاز Android 13 أو أحدث، والتأكد من استمرار الخدمة وظهور إشعارها بعد التفعيل.
